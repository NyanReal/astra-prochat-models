# HOPPER /03 — 독립 팔 모듈 v5

**기존 `HOPPER_03_Legs_v4`의 어깨 규격에 맞춘 좌우 개별 GLB입니다. 본체 수정본이 아닙니다.**

| 항목 | 삼각형 수 |
|---|---:|
| L 팔 | 2,406 |
| R 팔 | 2,406 |
| 양팔 합계 | 4,812 |
| 기존 v4 본체 + 다리 | 25,058 |
| 기존 v4 + 양팔 임시 장착 | **29,870** |

## 먼저 사용할 파일

- `models/HOPPER_03_Arm_L_M1.glb`: 독립 L 모듈
- `models/HOPPER_03_Arm_R_M1.glb`: 독립 R 모듈
- `docs/socket_spec.json`: 기계가 읽는 결합 치수·위치·쿼터니언·배율
- `docs/H03_M1_INTERFACE_KO.md`: 원점, 축, 장착 방법과 주의사항

각 팔의 원점은 연결부 중심이며, 기본 transform은 위치 0 / 회전 identity / 배율 1입니다. 모델 단위는 미터입니다. 좌우를 음수 배율로 복제하지 않고, 실제 정점·법선·삼각형 방향에 대칭을 반영했습니다. R/L 명칭은 **원본 노드 이름을 보존**합니다. 원본 R은 +X, L은 −X이며 화면상의 좌우가 아닙니다.

`preview/FitCheck.glb`는 원본 v4에 독립 팔을 임시 배치한 검사 장면입니다. 별도 팔 모듈을 사용할 때 이 파일로 본체를 교체할 필요가 없습니다. `reference/HOPPER_03_Legs_v4.glb`는 원본과 바이트 단위로 같은 참조 복사본입니다.

## 팔 구조

실제 메시로 암형(받이) 슬리브 연결부, 기준 표시, 6개 체결부, 출력 저널, 상완 스파와 보강 웹, 안쪽 면과 테두리를 가진 어깨 장갑, 팔꿈치 클레비스·관통축·베어링, 전완 프레임과 장갑, 뒤쪽 댐퍼·로드·씰·핀, 서비스 호스, 손목 축, 손바닥 및 뭉뚝한 다섯 손가락을 구성했습니다.

부품을 개별 노드로 분리하고 어깨·팔꿈치·손목 피벗과 미래의 손/도구 교체를 위한 `Arm_L_09_ToolPort`, `Arm_R_09_ToolPort` 기준점을 넣었습니다. **이번 파일은 고정된 기준 자세의 팔입니다.** 팔 운동 애니메이션, 스키닝, IK, 유압 기구 솔버, 임의 관절각 간섭 검증은 포함하지 않습니다. 피벗이 있다는 것이 완성된 작동 리깅을 뜻하지 않습니다.

## 프리뷰 실행

ZIP 전체를 압축 해제한 뒤 그 폴더에서 실행합니다. Python 표준 라이브러리만 필요합니다.

```bash
python start_preview.py
```

브라우저가 자동으로 열립니다. 자동 열기가 필요 없으면 다음과 같이 실행합니다.

```bash
python start_preview.py --no-open --port 8001
```

기본 연결은 실행한 컴퓨터의 loopback 주소로만 제한됩니다. 같은 네트워크의 태블릿에서 보려면 직접 `--lan`을 선택하고 콘솔에 표시되는 안내를 따릅니다. 이 경우 서버를 끌 때까지 패키지 안의 파일을 해당 네트워크에서 읽을 수 있습니다. 종료는 Ctrl+C입니다.

페이지 전체는 정적 HTML/CSS/JS입니다. CDN, 계정, 외부 API, 빌드 도구가 필요하지 않습니다. `preview/index.html`의 `file://` 경로용 base64 모델 로더도 포함되어 있지만, 파일 앱·브라우저의 로컬 HTML 실행 제한은 기기마다 다르므로 로컬 정적 서버 방식을 우선 사용하십시오. 프리뷰를 누르기 전에는 GLB를 읽지 않습니다. 프리뷰는 장착 검사에 필요한 본체까지 약 11.6MB의 GLB를 읽으며, 개별 팔 GLB는 각각 약 1.28MB입니다.

### 프리뷰 기능

좌우 모듈 / L 단독 / R 단독 / 임시 장착을 전환할 수 있습니다. 분리 슬라이더는 장착 축을 따라 위치를 바꾸는 **검사용 배치 기능**입니다. 팔 애니메이션으로 GLB에 저장된 동작이 아닙니다. 팔 장갑 숨기기, 연결부 내부만 표시, 팔꿈치·손목·본체 결합부 확대, 와이어, 자동 회전, PNG 저장, UV 확인 기능이 있습니다.

임시 장착 상태에서는 원본의 `Cockpit_Open` 3초, `Cockpit_Close` 3초, `Cockpit_Cycle` 8초 애니메이션을 그대로 재생합니다. 개별 팔 GLB 자체에는 애니메이션 클립이 없습니다.

## 텍스처와 UV

팔 전용 2048×2048 Base Color / ORM / Tangent Normal PNG를 별도 제공하며 각각의 GLB에도 내장했습니다. 좌우 팔은 같은 아틀라스를 사용하지만 UV 배치 영역은 서로 겹치지 않습니다. 독립 배치 영역은 총 **450개**입니다. 일부 영역 안에는 베벨 면용 작은 섬이 여러 개 들어가므로, 이 수를 연결 성분 기준 UV 아일랜드 개수와 동일하게 해석하지 마십시오.

사용 UV 면적의 **85.91%**를 외장 장갑에 배정했습니다. 장갑의 평균 선형 밀도는 어두운 골격의 **4.706배**입니다. 아틀라스 전체 대비 실제 사용 UV 면적은 약 77.74%, 각 배치 영역 주위 거터는 6px입니다. 작은 프레임과 내부 기계에는 낮은 밀도를 적용했습니다. 텍스처는 이 메시의 UV를 기준으로 작성한 절차적 페인팅이며, 이번 팔 작업에서 새 이미지 생성 모델로 만든 텍스처는 아닙니다.

`ORM`의 R/G/B는 각각 occlusion / roughness / metallic입니다. Base Color는 sRGB로, ORM과 Normal은 비색상 데이터로 취급하는 설정이 GLB에 구성되어 있습니다. 두 개별 GLB에는 동일한 아틀라스가 각각 내장되므로, 실제 게임에서 함께 사용할 때 동일한 텍스처·머터리얼을 공유하도록 정리할 수 있습니다.

## 검증 범위

실제 출력 GLB의 삼각형 수, 액세서 범위, 정점 유한값, 법선·탄젠트, UV 범위와 비중첩 배치, 좌우 대칭, 원점·축, 원본 보존, 장착 transform을 검사했습니다. 원본 노드/메시/재질/텍스처/액세서/애니메이션 및 원본 바이너리 구간을 보존했는지도 검사했습니다.

원본 콕핏 열기 동작의 181개 시점과 고정된 팔 자세에서 VTK로 실제 삼각형 표면 교차를 검사했습니다. 팔–본체, 팔–움직이는 콕핏, 팔 댐퍼–장갑, 주요 하중 프레임–장갑의 검사 대상에는 교차가 없었습니다. 의도적으로 맞물리는 내부 볼트·핀·베어링 전체를 서로 분리된 물체로 취급한 검사는 아닙니다. 이는 연속 스윕·완전 포함·모든 팔 관절 자세·제조 공차·구조 하중을 보증하지 않습니다.

Chromium/WebGL2에서 실제 패키지의 GLB를 렌더링하고 UI를 조작했습니다. 이 실행 환경은 브라우저의 localhost 직접 이동을 차단하므로, 브라우저 검사는 패키지 HTML/JS와 내장 base64 GLB를 메모리에 로드해 진행했습니다. 정적 HTTP 서버의 파일 응답은 별도로 확인했습니다. 실제 iPad/Safari, Blender, Unreal에서의 실행 검증은 하지 않았습니다.

상세 결과는 `docs/asset_report.json`, `docs/clearance_report.json`, `docs/browser_verification.json`, `docs/unit_tests.txt`에 있습니다.

## 재생성

원본 GLB와 작성 소스가 모두 들어 있습니다. Python 3.10 이상, NumPy, SciPy, Shapely, Pillow가 필요합니다. 검증용 VTK와 Playwright는 일반 열람에 필요하지 않습니다.

```bash
python -m pip install -r source/requirements.txt
python source/build.py
python -m unittest discover -s tests -p "test_*.py" -v
```

간섭 보고서를 새로 계산하려면 VTK를 설치하고 `python tests/check_clearance.py`를 먼저 실행합니다. Chromium 캡처·UI 검사는 Playwright, Chromium, Xvfb를 갖춘 Linux 환경용으로 작성했습니다. 재생성은 `models`, `textures`, 검사 장면과 관련 JSON을 덮어쓰므로, 직접 수정한 파일이 있다면 별도 복사본에서 실행하십시오. 연결 치수의 근거인 원본 `reference` GLB는 수정하지 않습니다.

패키지에는 폰트 파일이 포함되어 있지 않습니다. 텍스처의 문자 재생성은 운영체제의 DejaVu 폰트를 우선 사용하며, 없으면 Pillow 기본 폰트로 대체되어 글자 모양이 달라질 수 있습니다.
